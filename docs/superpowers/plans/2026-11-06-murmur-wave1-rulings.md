# Murmur wave 1: controller rulings

Decisions made during the subagent-driven build of wave 1, in the order they were made.
Each line says what was decided, why, and what it costs if wrong.
The spec is the binding authority; these rulings filled gaps or resolved conflicts in the plan.

- Ruling 1: Execute Task 16 (map) before Task 15 (live screen) - T15's tests exercise MapView highlight and phase filter, and T16 depends only on core types - costs nothing if wrong, the order is independent otherwise.
- Ruling 2: The secret-assignment rule matches only environment-style names `[A-Z][A-Z0-9_]*` (uppercase, case-sensitive), so `key=<token>` lowercase is handled by the token patterns and keeps ` end` - matches the plan's test and env-var convention - if wrong, a lowercase `api_key=...` line keeps its value unless a token pattern catches it.
- Ruling 3: Work on branch `wave-1` in ~/Projects/murmur instead of a separate worktree - new repo with no other work, and memory records linked node_modules in worktrees getting committed - if wrong, nothing is lost; the branch is isolated from main.
- Ruling 4: Pause is keyed by session using CLAUDE_CODE_SESSION_ID (plan's own conditional in Task 6), with project-folder fallback when it is missing - hook-facts confirms the variable exists for hooks and ! commands - if wrong, pause falls back to the folder rule.
- Ruling 5: TaskCreated/TaskCompleted are optional inputs; fallbacks must not depend on them, and an inferred plan with no tasks is the normal case on this Claude Code build - no such tool exists here - if wrong, the inferred plan is emptier than it could be.
- Ruling 6: Reducer ignores SubagentStop events with an empty agent_type and no matching SubagentStart (prompt-suggestion generator) - observed in the interactive fixture - if wrong, a real empty-type subagent would be hidden.
- Ruling 7: Amend Ruling 1: assignment regexes anchor with `^[+\- ]?[ \t]*(export[ \t]+)?` instead of `^\s*` - spec requires secrets scrubbed and hooks never slowing Claude; my earlier ruling fixed case-sensitivity, the `\s*` was incidental - if wrong, an assignment indented with a form feed is missed.
- Ruling 8: Widen plan's generic OpenAI pattern to `\bsk-[A-Za-z0-9_-]{20,}` (word boundary avoids matching inside words like "disk-") - spec's "scrub obvious secrets" outranks the plan's pattern, and sk-proj- is today's standard key - if wrong, a 20+ char identifier starting with "sk-" in normal text gets redacted.
- Ruling 9: Task 3 status-flow rules (task running->now, part/phase now/done derivation, only latest narrate makes things now) and repeated-map merge (new order/titles, keep detail by id, drop vanished ids) - plan states the outcome but not the edge rules - if wrong, the strip/plan may mark a part now or todo differently than a user expects.
- Ruling 10: A narrate naming a task but no part attaches its step (and other part fields) to that task's part when the task has one - the user expects work on task 2.2 to show on its map part - if wrong, a step lands on a part Claude did not name.
- Ruling 11: Two tasks may show "now" at once when Claude marked both running and neither done - follows Claude's own statuses - if wrong, the plan panel shows two current tasks.
- Ruling 12: Amend Ruling 1: the latest narrate promotes its part (and task) to now only when the other rules do not already make it done - a finished part must not stay "now" after the work ends - if wrong, the current part briefly shows done while Claude still works on it after marking it done.
- Ruling 13: Task 4 file touches merge into narrate's role-only entries by path; role-only entries with no real Edit/Write are dropped from files - avoids showing fake 0/0 touches - if wrong, a file Claude described but only read never appears in "Files touched".
- Ruling 14: Task 4 stuck counting: consecutive failed narrate steps per part (reset by a done/running step) and consecutive PostToolUseFailure on the same tool+target (reset by a success) - plan gives thresholds, not resets - if wrong, stuck flags fire earlier or later than a user expects.
- Ruling 15: Accept Task 4 deviations above - each matches the spec's intent (no fake touches, no stale needs-you, paths merge) - if wrong, minor display differences.
- Ruling 16: A pending risky flag also stops being pending on the next UserPromptSubmit, Stop or SessionEnd - a denied command never gets a PostToolUse - if wrong, a still-running long command loses its pending marker at Stop.
- Ruling 17: Ratify deviation: risky pending also ends on PostToolUseFailure with the same tool_use_id - the command finished (failed) - if wrong, none.
- Ruling 18: Needs-you also clears on PostToolUseFailure - an approved tool that exits nonzero must not leave "needs your permission" up - if wrong, none.
- Ruling 19: catchUp details: failing = checks newly fail + newly failed steps; multiple task titles joined with " and " in plan order; Agent k = 1-based index in request agents; null when request missing - plan gives the format but not these edges - if wrong, the catch-up line wording differs slightly.
- Ruling 20: Task titles read `task_subject ?? subject ?? task?.subject ?? title ?? task_description ?? description` - hook-facts documents task_subject; my earlier list omitted it - if wrong, none.
- Ruling 21: catchUp treats a request missing from `before` as an empty request (so progress made in a new request while away is reported); null only when the request is missing from `after` or nothing changed - matches the "since you last looked" purpose - if wrong, a brand-new request shows a catch-up line on first view.
- Ruling 22: Task 6 pause API is `isPaused(cwd, sessionId?)` / `setPaused(cwd, paused, sessionId?)`: keyed by session when CLAUDE_CODE_SESSION_ID is known, by project folder otherwise (per Ruling 4) - plan signature lacked the session - if wrong, callers pass one extra optional argument.
- Ruling 23 (corrected mid-task): Task 7 headless = CLAUDE_CODE_ENTRYPOINT starts with "sdk" OR CLAUDE_CODE_SESSION_ATTENDED "0"; applies to all hooks - from hook-facts - if wrong, a non-sdk headless runner (e.g. CI wrapper) uploads unless SESSION_ATTENDED=0 is set.
- Ruling 24: Narration instruction is injected on every SessionStart source (startup/resume/clear/compact) so it survives compaction - spec risk "narration after compaction" - if wrong, the instruction appears twice in context after a resume.
- Ruling 25: Accept Task 7 decisions: a single event answered 413 is dropped (else it blocks the queue forever); 5 MB = 5,000,000 bytes; SessionStart flushes in a detached --flush child; flush(budgetMs=3000) - keep the hook from blocking Claude - if wrong, one oversized event is lost from the view.
- Ruling 26: Accept: command files run `murmur <cmd> || true` without "$PWD" (Claude Code refuses quoted text in ! commands) and the CLI uses process cwd; /murmur:login takes no server arg (MURMUR_SERVER or terminal `murmur login <server>` for self-hosters); pnpm allowBuilds esbuild:false - forced by Claude Code and pnpm 12 - if wrong, a command run from a subfolder keys to that folder's git root (same project in practice).
- Ruling 27: openDb returns the Db plus a way to close it: `openDb(url): Promise<{ db: Db; close(): Promise<void> }>`; migrations folder = env MIGRATIONS_DIR if set, else resolved from import.meta.url - Task 10+ build on this contract and deploy may bundle - if wrong, callers destructure one extra field.
- Ruling 28: Task 10 auth details: dev login uses a negative fake github_id; requireUser/requireIngest 401 JSON; requireSameOrigin (JSON + Origin == baseUrl) for every cookie mutating route; device approve case/dash-insensitive, 404 for unknown/expired/approved; token returned once then 410; GitHub provider injectable via Deps for tests - plan gives the endpoints but not these edges - if wrong, a client sending no Origin (some proxies strip it) cannot approve or log out.
- Ruling 29: Add in-process rate limits now: POST /api/device/approve at most 10 failed attempts per user per 10 minutes and 30 per IP per 10 minutes (429 {error:'rate_limited'}); POST /api/device/start at most 20 per IP per 10 minutes. ponytail: in-memory, single instance; move to Postgres or a shared store with multiple instances - security measures are not simplified away and a guessed code streams a victim's code to an attacker - if wrong, a user mistyping codes 10 times waits 10 minutes.
- Ruling 30: Task 11 ingest/stream details: guard on the route; 413 too_large/too_many, 400 invalid with index, all-or-nothing batch; token machineId overrides event machineId; session upsert rules (title set once, last_event_at monotonic); machineName joined from tokens; tuple cursor with 5,000 cap and hasMore; SSE ping 20 s; assumptions GET/PUT; delete in one transaction - plan names routes, not these edges - if wrong, one bad event rejects its whole batch until the plugin drops or fixes it.
- Ruling 31: Accept Task 11 additions: 400 for non-uuid id or unparsable ts, NUL characters stripped, events returned with the session's cwd; workspaceConcurrency 1 to stop timing flakes - prevents Postgres rejecting batches forever and keeps live/reload identical - if wrong, per-event cwd changes mid-session show paths relative to the first cwd.
- Ruling 32: Task 12 config: devLogin only when MURMUR_DEV_LOGIN=1 and NODE_ENV != production; TRUST_PROXY=1; cookieSecure from https BASE_URL; loadConfig pure and tested; SPA fallback; "web app not built" 404 when web/dist missing; SIGTERM/SIGINT graceful close; retention also sweeps expired web_sessions and device_codes - carried from Tasks 9/10 reviews - if wrong, a dev deploy forgetting NODE_ENV=production with MURMUR_DEV_LOGIN=1 exposes dev login.
- Ruling 33: Server test flakiness is fixed in Task 12 before review (suite must pass 5 consecutive full `pnpm -r test` runs) - user's standing instruction to fix flakes - if wrong, nothing; tests only.
- Ruling 34: /device opened while logged out keeps its code: the web app stores the code in sessionStorage before redirecting to /auth/github and returns to /device?code=... after login (server keeps redirecting to /, no returnTo) - avoids an open-redirect surface on the server - if wrong, a user with storage disabled re-opens the link from the terminal.
- Ruling 35: Task 13 UI details: hand-written router; device states and error copy; sessions row content and live marker (< 2 min, not ended); two-click Revoke (no browser dialog); typed "delete my account"; 960px column, no horizontal scroll at 375px; session routes are placeholders until Task 15 - plan gives pages and copy but not these - if wrong, wording or layout differs slightly from the author's taste.
- Ruling 36: Controller visual findings enter the fix loop as Important (author's standing pixel-perfection instruction): header content held to the 960 column; nav links grey (--muted, underline on hover) not blue; login shows the "What Murmur sends" panel once without a duplicate link; empty-state commands in code style; delete phrase shown in code style. The delete-account button stays grey (no red), because red is reserved for stuck or failing - if wrong, destructive action looks less alarming.
- Ruling 37: Session titles: server cuts the first prompt at a word boundary within 79 code points and appends "…" when the prompt was longer (small server change allowed in this web task, test updated) - avoids mid-word cuts like "watchlist stock a" - if wrong, titles are one character shorter.
- Ruling 38: Task 14 live data: page through hasMore before opening the stream; dedupe+sort client array; reconnect with 1/2/4..15 s backoff, gap fetch through api.events (401 path), 404 = error; viewAt reduces events up to ts; lastLooked returned value stays stable while the user is looking - plan names the hooks, not these edges - if wrong, a reconnect gap of more than 15 s shows briefly stale data.
- Ruling 39: Amend Ruling 1: the server's SSE handler writes `event: ready` (data `{}`) right after bus.subscribe; the client sets status live, resets backoff, and runs one catch-up fetch from the cursor on `ready` (dedupe makes overlap free). Small server change in stream.ts allowed in this task - closes the subscribe gap without polling - if wrong, one extra events request per connect.
- Ruling 40: Window focus does not change useLastLooked's returned value; blur still writes storage; the value changes only on mount or visible-after-hidden - side-monitor use keeps the window blurred while watching - if wrong, catch-up only refreshes after a real tab switch.
- Ruling 41: Task 16 map specifics: node 160x40, centre 180x44, fixed feature slots (8, then second ring x1.35), kind-specific columns, goal caption for non-feature kinds, inverted goal box, stuck border at failures>=3, phase tag "phase n", up to 2 agent chips then +N more, 35% dimming over opaque backing, a11y node buttons, empty-state copy - plan gives the rules, not the numbers - if wrong, the map looks different from the mockups in spacing only.
